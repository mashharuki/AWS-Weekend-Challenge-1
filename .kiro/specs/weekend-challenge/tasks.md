# 実装計画

## 実装上の前提

- 各サブタスクは 1〜3 時間で完了できる粒度とする。
- `(P)` は依存先の完了後に、他タスクとファイル・責務が重ならず並行実施できる作業を表す。
- 実装時は設計書の型契約、最小権限、公開状態遷移を変更せず、契約変更が必要な場合は先に設計を再承認する。

- [ ] 1. 開発基盤と共通契約を整備する
- [ ] 1.1 ワークスペースの依存関係と実行スクリプトを追加する
  - バックエンド、フロントエンド、CDK に必要な SDK、検証、UI、インフラ検査の依存関係を追加する。
  - フォーマット、静的解析、ビルド、テスト、CDK 合成を一貫して実行できるスクリプトを定義する。
  - 依存関係のインストール後に各パッケージの既存ビルドが成功することを確認する。
  - _Requirements: 7.1, 8.2_
- [ ] 1.2 生成・投稿・実行・設定の共有型と入力スキーマを定義する
  - `GenerationRun`、`DraftPost`、`PublishedPost`、API DTO、エラー分類、`AppConfig` を strict TypeScript で定義する。
  - 日時、UUID、URL、Markdown、投稿状態、実行状態の境界検証を Zod で提供する。
  - 危険な型キャストや `any` を使わず、すべての後続モジュールが共有契約を利用できる状態にする。
  - _Requirements: 1.2, 3.3, 5.1, 6.4, 7.4_

- [ ] 2. コンテンツと実行の永続化を実装する
- [ ] 2.1 DynamoDB の実行・投稿リポジトリを実装する (P)
  - 日付ベースの `runId` に対する条件付き開始、最新投稿・最新実行の取得、失敗記録を実装する。
  - 投稿の `PUBLISHED` 化と対応する実行の `SUCCEEDED` 化を単一の DynamoDB トランザクションで確定する。
  - 重複実行、状態遷移違反、トランザクション競合を分類済みエラーとして返す。
  - _Requirements: 1.2, 1.3, 3.3, 5.1, 5.2, 5.3_
  - _Boundary: backend persistence and shared contracts_
- [ ] 2.2 S3 Markdown ストアと非公開草案ストアを実装する (P)
  - 投稿本文を投稿 ID に対応するキーへ保存・取得し、草案は公開本文と分離する。
  - 本文の content type、サイズ上限、読み取り失敗を検証・分類する。
  - DynamoDB の公開トランザクション前には公開 API から本文に到達できないことを保証する。
  - _Requirements: 3.2, 3.3, 3.4, 5.2, 6.3_
  - _Boundary: backend object storage adapter_
- [ ] 2.3 永続化の状態遷移と障害をテストする
  - 同一日付の二重開始が一つの実行記録だけを作ることを検証する。
  - S3 保存失敗と DynamoDB トランザクション失敗で公開投稿が残らないことを検証する。
  - PUBLISHED 以外の投稿が一覧・詳細取得に現れないことを検証する。
  - _Requirements: 1.3, 3.4, 5.1, 5.2, 8.2_
  - _Depends: 2.1, 2.2_

- [ ] 3. 信頼できる情報収集とエージェント生成を実装する
- [ ] 3.1 許可ソースの収集・正規化アダプターを実装する (P)
  - HTTPS の許可オリジンだけを取得対象とし、URL、content type、応答サイズ、タイムアウトを検証する。
  - 取得結果をタイトル、抜粋、公開日、URL の `SourceDocument` へ正規化する。
  - 十分な候補を取得できない場合は、公開せず再試行可能な収集失敗を返す。
  - _Requirements: 2.1, 2.2, 2.4, 6.4_
  - _Boundary: backend source collection adapter_
- [ ] 3.2 Strands と Bedrock Nova の生成アダプターを実装する (P)
  - `amazon.nova-lite-v1:0` を初期モデル設定とし、モデル ID は型付き設定から注入する。
  - 外部本文を非信頼コンテキストとしてシステム指示から隔離し、外部書込みツールを公開しない。
  - 英語 Markdown、タイトル、具体的アイデア、出典 URL を含む構造化草案を要求し、モデル・一時障害を分類する。
  - _Requirements: 2.2, 2.3, 3.1, 3.2, 6.1_
  - _Boundary: backend agent adapter_
- [ ] 3.3 Bedrock Guardrails と公開前コンテンツ検証を実装する
  - 取得本文への prompt-attack 検査と生成結果への Guardrails 検査を適用し、拒否・検査不能の結果は公開しない。
  - 英語、必須 Markdown 構造、空本文、許可 URL、HTML 無効化を検証する。
  - 検証済み草案だけを永続化層へ渡し、失敗理由を安全なエラーコードへ変換する。
  - _Requirements: 2.4, 3.1, 3.2, 3.4, 6.1, 6.4_
  - _Depends: 1.2, 3.1, 3.2_
- [ ] 3.4 収集・生成・安全性のユニットテストを追加する
  - 許可外 URL、タイムアウト、候補不足、Bedrock 一時障害を検証する。
  - prompt attack、危険な HTML、英語でない・空の草案を拒否することを検証する。
  - 正常な草案が `DraftPost` 契約を満たすことを検証する。
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.4, 6.4, 8.2_
  - _Depends: 3.1, 3.2, 3.3_

- [ ] 4. 自律生成ワークフローのハンドラーを実装する
- [ ] 4.1 実行開始・公開・失敗記録の Lambda ハンドラーを実装する
  - `StartRun` は重複を正常終了として返し、新規実行だけをエージェント処理へ渡す。
  - `ResearchAgent`、`ValidatePublish`、`RecordFailure` の各ハンドラーを責務ごとに接続する。
  - ログには runId、stage、status、durationMs、errorCode だけを記録し、本文・秘密値・生レスポンスを出力しない。
  - _Requirements: 1.2, 1.3, 2.4, 3.3, 3.4, 5.1, 5.2, 5.3, 8.1_
  - _Depends: 2.1, 2.2, 3.3_
- [ ] 4.2 StateMachine の状態定義と統合テストを実装する
  - 新規実行、重複実行、収集失敗、Guardrails 拒否、保存失敗を状態遷移として定義する。
  - 回復可能な外部失敗は指数バックオフで最大 2 回再試行し、最終失敗は `RecordFailure` に送る。
  - 成功時だけ公開済み投稿と成功実行記録が揃い、失敗時は未公開であることを統合テストで確認する。
  - _Requirements: 1.1, 1.3, 1.4, 2.4, 3.4, 5.1, 5.2, 5.3, 8.1_
  - _Depends: 4.1_

- [ ] 5. 読み取り専用 API を実装する
- [ ] 5.1 Hono のヘルスチェックと公開投稿 API を実装する (P)
  - `/health`、投稿一覧、投稿詳細、最新実行状態の GET ルートを実装する。
  - `limit` と `postId` を検証し、未公開・不存在投稿、内部障害を定型 JSON エラーへ変換する。
  - API 応答から S3 キー、IAM 情報、秘密値、内部スタックトレースを除外する。
  - _Requirements: 4.1, 4.3, 4.4, 5.4, 6.3_
  - _Boundary: backend Hono read API_
- [ ] 5.2 API の統合テストを追加する
  - 最新順の一覧、投稿本文の結合、空状態、非公開投稿、無効入力を検証する。
  - API が読み取りだけを提供し、書込みルートを公開しないことを検証する。
  - _Requirements: 4.1, 4.3, 4.4, 5.4, 6.3, 8.2_
  - _Depends: 5.1, 2.1, 2.2_

- [ ] 6. 閲覧 UI を実装する
- [ ] 6.1 Tailwind と安全な Markdown 表示基盤を追加する (P)
  - Tailwind のビルド設定と、HTML を実行しない Markdown 表示ライブラリを追加する。
  - 見出し、段落、リスト、許可プロトコルのリンクを一貫して表示できる基盤を作る。
  - _Requirements: 4.2, 6.4_
  - _Boundary: frontend styling and Markdown renderer_
- [ ] 6.2 投稿・実行状態の API クライアントと画面状態を実装する
  - 投稿と最新実行を型付き DTO で取得し、`loading`、`ready`、`empty`、`error` を分離して扱う。
  - 投稿取得が成功した場合、実行状態の取得失敗が本文表示を妨げないようにする。
  - _Requirements: 4.1, 4.4, 5.4_
  - _Depends: 5.1_
- [ ] 6.3 最新投稿・履歴・実行証跡の画面を実装する
  - 最新の公開投稿を初期表示し、過去投稿はタイトルと生成日時で選択可能にする。
  - Markdown、空状態、失敗を含む実行状態を読みやすく表示する。
  - 利用者が手動生成・編集できる操作を UI に追加しない。
  - _Requirements: 1.4, 4.1, 4.2, 4.3, 4.4, 5.4_
  - _Depends: 6.1, 6.2_
- [ ] 6.4 UI のコンポーネント・E2E テストを追加する
  - 最新投稿、投稿選択、Markdown 表示、空状態、実行失敗状態を検証する。
  - 生 HTML や危険なリンクが実行・描画されないことを検証する。
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 5.4, 6.4, 8.2_
  - _Depends: 6.3_

- [ ] 7. CDK の設定とストレージ Construct を実装する
- [ ] 7.1 型付き CDK 設定、論理 ID、Stack 合成を整備する (P)
  - チャレンジ環境のリージョン、JST スケジュール、`amazon.nova-lite-v1:0`、許可ソース、ログ保持、削除ポリシーを外部設定として定義する。
  - すべての Construct と資源 ID を集中管理し、Stack にタグと公開 URL の Output を追加する。
  - 雛形 Stack を `CreativeAgentStack` と用途別 Construct を合成する構成へ移行する。
  - _Requirements: 7.1, 7.4, 8.2, 9.4_
  - _Boundary: CDK configuration and stack composition_
- [ ] 7.2 コンテンツ・実行ストアと最小権限を CDK で定義する
  - DynamoDB のオンデマンド、暗号化、PITR、GSI と、S3 の暗号化、Block Public Access、SSL 強制を定義する。
  - チャレンジ環境の明示的な削除ポリシー、S3 の自動オブジェクト削除、ログ削除を設定する。
  - Read Lambda と Publish Lambda の DynamoDB/S3 権限を分離し、必要なトランザクション操作だけを許可する。
  - _Requirements: 3.3, 5.1, 5.2, 6.1, 6.3, 7.1, 7.3_
  - _Depends: 7.1_
- [ ] 7.3 生成用 Lambda、StateMachine、Scheduler、DLQ、監視を CDK で定義する
  - 各ハンドラーを Node.js 20 Lambda としてバンドルし、Bedrock、Secrets Manager、DynamoDB、S3 への最小権限を付与する。
  - EventBridge Scheduler の JST cron、retry policy、SQS DLQ、DLQ/ターゲット失敗アラームを定義する。
  - Step Functions の Retry/Catch、CloudWatch Logs、`RecordFailure` への終端分岐、Guardrails 使用権限を定義する。
  - _Requirements: 1.1, 1.2, 1.4, 2.4, 5.1, 5.3, 6.1, 6.2, 7.1, 8.1_
  - _Depends: 4.2, 7.1, 7.2_
- [ ] 7.4 読み取り API と Web 配信を CDK で定義する
  - HTTP API の GET ルート、route-level throttling、Read Lambda の予約同時実行数を定義する。
  - Vite 生成物を非公開 S3 バケットへ配備し、CloudFront OAC と `/api/*` の API オリジン、キャッシュ無効ポリシーを設定する。
  - API を認証なし公開読み取りと明記し、CORS をアクセス制御として使用しない。
  - _Requirements: 4.1, 4.3, 5.4, 6.3, 7.1, 7.2_
  - _Depends: 5.1, 6.3, 7.1, 7.2_
- [ ] 7.5 CDK のセキュリティ・配備構成を検証する
  - cdk-nag を Stack に適用し、不可避な抑制は理由と対象を最小化して記録する。
  - 合成テンプレートで、S3 非公開・暗号化、DynamoDB 設定、Scheduler DLQ、アラーム、GET 限定 API、最小権限、ログ保持・削除を assertions で検証する。
  - `cdk synth` と `cdk diff` が再現可能に実行できることを確認する。
  - _Requirements: 6.1, 6.2, 6.3, 7.1, 7.2, 7.3, 7.4, 8.2, 8.3_
  - _Depends: 7.2, 7.3, 7.4_

- [ ] 8. 実環境の統合検証と運用証跡を整備する
- [ ] 8.1 AWS 上で配備前後のスモークテストを実行する
  - `cdk synth`、配備、CloudFront の UI、公開 API、DynamoDB/S3 の公開状態、削除操作を順に検証する。
  - 運用ログに秘密値・本文全文が含まれないこと、削除後に管理対象資源が残らないことを確認する。
  - _Requirements: 6.1, 6.3, 7.1, 7.2, 7.3, 8.1, 8.3, 9.4_
  - _Depends: 7.5_
- [ ] 8.2 自律実行と失敗経路の受入テストを実行する
  - スケジュール相当の入力で生成を起動し、実行記録、英語 Markdown、公開投稿、UI 表示の連鎖を確認する。
  - 重複実行、候補不足、Guardrails 拒否、StateMachine 失敗、Scheduler 配信失敗が重複公開なく適切な記録または DLQ/アラームに到達することを確認する。
  - チャレンジ提出に使える生成証跡を保存する。
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.4, 3.1, 3.2, 3.3, 3.4, 4.1, 5.1, 5.2, 5.3, 5.4, 8.1_
  - _Depends: 8.1_

- [ ] 9. 提出資料と運用ドキュメントを完成させる
- [ ] 9.1 README と AWS アイコン使用の draw.io 図を作成する (P)
  - アプリケーションの目的、自律生成フロー、主要 AWS サービス、セットアップ、ビルド、配備、利用、削除手順を README に記載する。
  - S3/CloudFront、HTTP API/Lambda、Scheduler/Step Functions、Bedrock、DynamoDB、S3、DLQ のデータフローを draw.io で図示する。
  - CDK Output と実際のコマンドに基づき、非公開手順なしで再現できることを確認する。
  - _Requirements: 7.1, 7.2, 9.1, 9.2, 9.3, 9.4_
  - _Boundary: repository documentation and architecture diagram_
- [ ] 9.2 AWS Builder Center 向け英語記事を作成する (P)
  - 500 語以上、指定タイトル接頭辞、`agents` タグ、ビジョン、構築過程、AWS アーキテクチャ、学び、公開リンクを含む Markdown を作成する。
  - 自律スケジュール実行と生成結果の証跡を、記事またはリンク先で確認できるようにする。
  - 提出期限前に公開リンクと要件チェックリストを確認できる状態にする。
  - _Requirements: 5.4, 10.1, 10.2, 10.3, 10.4_
  - _Boundary: Builder Center article asset_
